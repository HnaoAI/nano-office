# T2.21 : Copier automatiquement la sélection (réglage)

**Suivi** : Issue [#118](https://github.com/HnaoAI/nano-office/issues/118), le statut se lit sur le tableau Kanban
**Dépend de** : rien
**Taille estimée** : S
**Lot** : M. Améliorations du PO (idées recueillies avant la collaboration en ligne)

## User story

En tant qu'utilisateur qui copie souvent des morceaux de texte, je veux qu'un texte sélectionné à la souris soit
copié tout seul, comme avec Ctrl/Cmd+C, afin de gagner un geste.

## Décisions du product owner (2026-11-05)

- C'est un **réglage, éteint par défaut** : une famille habituée à Word sélectionne souvent un mot pour le remplacer par
  Ctrl+V, et la copie automatique remplacerait ce qu'elle avait copié avant.
- Seule une sélection faite **à la souris** est copiée, quand on lâche le bouton : glisser, double clic, triple clic,
  Shift+clic. Une sélection au clavier (Shift+flèches, Ctrl/Cmd+A) n'est pas copiée.

## Critères d'acceptation

1. Dans « Réglages », une case **« Copier automatiquement la sélection »**, décochée au départ, avec une phrase
   discrète : « Le texte sélectionné à la souris est copié, comme avec Ctrl+C (Cmd+C sur Mac). » Le style suit celui des
   Réglages existants (charte).
2. Case cochée : quand on lâche le bouton de la souris sur une sélection **non vide** dans le document, elle est copiée
   **exactement comme avec Ctrl/Cmd+C** (même texte et même mise en forme une fois collée, ailleurs ou dans Nano Buro).
   Un simple clic, qui ne sélectionne rien, ne change pas ce qui avait été copié.
3. Case décochée, ou sélection au clavier : rien n'est copié, le comportement d'aujourd'hui ne change pas.
4. Seul le texte du **document** est concerné, y compris dans un tableau ou un encadré. Les champs des boîtes (recherche,
   Mise en page, Réglages, texte d'une forme de schéma en cours de modification) ne copient rien tout seuls.
5. La copie automatique **ne modifie jamais le document** : pas d'étape d'annulation, pas de « Modifié », pas de
   travail commencé pour la mise à jour (H1).
6. Le réglage est retenu **sur l'ordinateur**, comme les réglages de l'assistant, et jamais dans le fichier `.nano`.
7. Si le navigateur refuse l'accès au presse-papiers, rien ne casse : pas de message d'erreur, la sélection reste, et
   Ctrl/Cmd+C fonctionne toujours.
8. Rien n'est envoyé sur le réseau (règle produit 2) : le presse-papiers reste sur l'ordinateur.
9. L'aide intégrée (A1) explique la case, dans la partie sur le copier-coller.

## Tests attendus

- Playwright : case décochée au départ ; cochée, une sélection à la souris (glisser, double clic) remplit le
  presse-papiers (permissions `clipboard-read` et `clipboard-write`), avec la mise en forme ; un simple clic et une
  sélection au clavier ne changent rien ; décochée, rien n'est copié ; le réglage survit au rechargement et n'est pas
  dans le fichier enregistré ; le document n'est pas marqué modifié.
- Cas limites : sélection d'emojis et d'accents, sélection dans un tableau, très long texte.

## Vérification manuelle

Sur le Mac avec Chrome et sur le PC avec Edge :

1. Copier un mot dans une autre application, puis sélectionner un mot dans Nano Buro, case décochée : Ctrl/Cmd+V colle
   le mot copié ailleurs (rien n'a changé).
2. Cocher la case dans Réglages, sélectionner une phrase en gras à la souris, puis coller dans un e-mail : la phrase est
   collée, en gras.
3. Double-cliquer sur un mot, puis coller plus loin dans le document : le mot est collé.
4. Sélectionner avec Shift+flèches : rien n'est copié.
5. Fermer et rouvrir Nano Buro : la case est toujours cochée.

# T2.18 : Ouvrir un fichier Word (.docx)

**Suivi** : Issue [#92](https://github.com/HnaoAI/nano-office/issues/92), le statut se lit sur le tableau Kanban
**Taille estimée** : M
**Lot** : K. Ouvrir un fichier Word

## User story

En tant que membre de la famille, je veux ouvrir dans Nano Buro un fichier Word que l'on m'a envoyé,
afin de le lire et de le modifier sans autre logiciel.

## Critères d'acceptation

1. « Ouvrir… » accepte aussi les fichiers `.docx`. Le fichier Word est **lu, jamais modifié** : il devient un **nouveau
   document** Nano Buro, avec un nouvel `id`, sans fichier courant. « Enregistrer » propose « Enregistrer sous… »,
   avec le nom du fichier Word et l'extension `.nano`. Ctrl/Cmd+S ne peut jamais écrire dans le `.docx`.
2. Sont repris, au plus près :
   - paragraphes, titres (styles « Titre 1 » à « Titre 3 », « Heading 1 » à « 3 ») ;
   - gras, italique, souligné, barré, couleur et surlignage (vers la couleur la plus proche de la palette) ;
   - police (vers la police intégrée la plus proche : avec empattements vers IBM Plex Serif ou EB Garamond, sans
     empattements vers IBM Plex Sans, à chasse fixe vers IBM Plex Mono) et taille ;
   - alignement, interligne, retrait, listes avec leurs niveaux, tableaux, images (réduites comme au lot D), liens,
     exposant et indice, sauts de page ;
   - format A4 et autres formats (ramenés à A4), orientation et marges.
3. Les éléments non repris (commentaires, suivi des modifications, zones de texte, formes, notes de bas de page, en-têtes
   et pieds de page complexes, champs) sont **signalés dans un message clair** : « Certains éléments n'ont pas pu être repris :
   … ». Le suivi des modifications est lu dans son état final (modifications acceptées), et le message le dit.
4. Un fichier Word protégé par mot de passe, abîmé ou d'un autre format (`.doc`, `.odt`) affiche un message clair, sans plantage.
5. Rien ne part sur le réseau : tout se fait dans le navigateur. Un fichier de 50 pages avec images s'ouvre en quelques secondes,
   avec un indicateur d'attente.
6. Les blocs reçoivent des identifiants neufs (règle produit 5). La copie de secours commence dès l'ouverture.

## Note technique

- Lecture de l'archive et du XML de Word dans le navigateur : bibliothèques sous licences acceptées seulement, justifiées
  dans la PR. Attention : `mammoth` (BSD) ignore volontairement les polices et les couleurs ; JSZip est sous double
  licence MIT ou GPL, à utiliser sous MIT.
- La conversion du XML de Word vers le JSON de Tiptap est du code pur dans `core/`, testé sur des fichiers `.docx` d'exemple
  rangés dans `tests/fixtures/`, dont un fichier exporté par Nano Buro (T2.7) : l'aller-retour Nano, Word, Nano garde tout.

## Hors périmètre

Ouvrir un `.doc` (ancien format) ou un `.odt`, garder le suivi des modifications et les commentaires, réécrire le `.docx`.
